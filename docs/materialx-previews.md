# MaterialX previews

Packaged materials now open the MaterialX surface generated by USD Toolbox 0.2.0.
The library list still loads only thumbnails. Opening 3D lazily loads Three.js's
MaterialX loader and node renderer; it chooses WebGPU or its WebGL2 backend.
Unpackaged authoring materials continue to use the texture preview.

`GET /packages/{package}/materialx-preview` requires an authenticated workspace
member with `materials.view` and visibility of the package's material. It verifies
the canonical package hash and size before conversion, then caches the XML/image
bundle by package hash and preview implementation version. Authorization precedes
both cached responses and ETag/304 handling. The response is private and must
revalidate. No package or published version is rewritten.

The inspector chooses the package pinned by the current published version. For an
unpublished material, it uses the latest package per variant. XML, constants,
procedural nodes and image connections come from that package, rather than the
loose authoring maps. The map inspection rail remains available separately.

The browser accepts only the bundle's PNG/JPEG images and decodes them before
translating the graph. Graph filenames cannot trigger arbitrary network requests.
Failed graphs/images report a limitation and explicitly fall back to texture
preview where available. Without maps, the preview reports an error and can retry.

Three.js 0.186.1 has partial MaterialX rendering support. Geometry displacement and
volume bindings are omitted only in the browser copy and disclosed in the UI.
Other unsupported inputs are reported from its strict interface validator and
translation log. This is not a claim of pixel-identical Omniverse rendering; the
canonical graph remains intact. Native MaterialX graphs with EXR dependencies are
preserved by Rust, but cannot currently be previewed by this browser adapter.

The independently versioned Rust library now preserves native MaterialX document
trees and dependencies through USDZ, and authors the `mtlx` USD render context.
See [its MaterialX contract](https://github.com/geyervalmont/usd-toolbox/blob/main/docs/materialx.md).
The current OPAL Omniverse extension still constructs a USD Preview Surface from
published maps. Switching that extension to bind the native `mtlx` material is the
next integration step; this change supplies its library/packaging foundation.

Validation: native/procedural/textured round trips, official MaterialX/OpenUSD
validators, WASM build, private preview/access/cache/integrity tests, browser
rendering of a native procedural graph and a real canonical library package.
